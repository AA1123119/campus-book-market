# 提示词迭代日志（全量）

> 本文件为报告附录 2 的全量版本，按"一次有效对话 = 一条记录"的粒度记录。
> 记录规范：每次向 AI 提问后 5 分钟内登记；必须写清"我改了什么、为什么改"，而不是只贴输出。

## 记录模板

| 字段 | 说明 |
|---|---|
| 编号 | 模块缩写 + 序号，如 AI-007 |
| 日期 / 成员 | 便于追溯 |
| 目标 | 这次要让 AI 完成什么 |
| 提示词（可脱敏摘录） | 关键描述，建议保留"约束 + 示例 + 禁止项" |
| AI 输出摘要 | 不要贴全文，写它做了什么、做了什么没做 |
| 人工修改 | 具体改了哪几处、依据是什么 |
| 轮次 | 该功能累计第几轮 |
| 评价 | 好 / 中 / 差，并写明原因（用于 6.4 统计） |

## 一、智能定价（AI 系列）

### AI-001（10-14，成员A）评价：差，轮次 1

- **目标**：根据原价与成色给出二手书建议价。
- **提示词**：`写一个 Java 方法，输入书籍原价和成色（1-5），输出建议售价。`
- **AI 输出摘要**：返回 `原价 × (成色/5)`，无学科差异、无区间、无理由。
- **人工修改**：判定不可用。4 成新按 80% 计价明显偏高，实际校园教材 4 成新成交价约为原价 40%-55%。
- **复盘**：需求里"定价"是领域问题，提示词没有提供任何领域知识，AI 只能给线性折算。

### AI-002（10-14，成员A）评价：中，轮次 2

- **目标**：引入学科系数与成色系数。
- **提示词要点**：给出 8 个学科的系数区间（0.5-0.65）；成色系数 1→0.55、5→0.95 线性；输出建议价与区间；加兜底"不低于 3 元、不高于原价 9 折"；要求 3 条 JUnit 断言兜底逻辑。
- **AI 输出摘要**：公式结构正确，生成了 `CATEGORY_FACTOR` 常量表与 `round()`；3 条单测覆盖了上限、下限与正常值。
- **人工修改**：发现供需修正用 `findAll()` 全表扫描，改为按 ISBN 查询；`conditionLevel` 未做 1-5 范围保护，补 `Math.max/min`。
- **评价**：约束写清楚后可用性显著提升。

### AI-003（10-15，成员A）评价：中，轮次 3

- **目标**：融合平台同款行情。
- **提示词要点**：同 ISBN 在售均价按 40% 权重融合；必须在 reason 中说明是否命中行情；无行情时给出降级文案。
- **AI 输出摘要**：融合逻辑正确，但查询未限定 `status='ON_SALE'`，把 SOLD 的历史高价也计入均价。
- **人工修改**：查询加状态条件；修正后同一本书建议价从 ¥31.2 降到 ¥23.99，符合预期。
- **复盘**：AI 不会主动想到"已售出商品不应影响当前定价"这种业务语义。

### AI-004（10-15，成员A）评价：良，轮次 4

- **目标**：让定价可解释、置信度可调。
- **提示词要点**：reason 必须逐步列出"原价 × 学科系数 × 成色系数 × 供需修正"，并给出区间；confidence 在无样本时 0.72，样本越多越高，上限 0.94。
- **AI 输出摘要**：reason 拼接完整，confidence 规则实现正确。
- **人工修改**：建议价先后顺序调整（先算区间再裁剪），修复边界偶发越界（45 元 5 成新曾出现建议价 40.51 > 上限 40.5）。

### AI-005（10-16，成员A）评价：优，轮次 5

- **目标**：补边界单测。
- **提示词**：`为 suggestPrice 写参数化测试，覆盖成色 1/3/5、原价 0、无 ISBN、同 ISBN 多本在售、置信度上下限。`
- **AI 输出摘要**：生成 7 条参数化测试，覆盖了预期分支。
- **人工修改**：仅调整断言中的浮点比较为 `compareTo`。

## 二、订单与并发（ORDER 系列）

### ORD-001（10-17，成员B）评价：差，轮次 1

- **提示词**：`实现订单创建：校验书籍在售、买家不能是卖家，创建订单并把书籍状态改为 LOCKED。50 并发下怎么保证不超卖？`
- **AI 输出摘要**：功能正确；并发问题回答"给方法加 synchronized"。
- **人工判断**：不可用。JVM 锁在多实例部署下失效，且会拖慢吞吐。
- **复盘**：把"不要使用 JVM 锁，请给出数据库层方案"写进提示词模板。

### ORD-002（10-18，成员B）评价：中，轮次 2

- **提示词**：`不要用 synchronized。给出数据库层的实现，要求一条语句同时完成校验与置位，并说明如何判断是否成功。`
- **AI 输出摘要**：给出 `update t_book set status='LOCKED' where id=? and status='ON_SALE'`，判断影响行数为 1 才继续建单。
- **人工修改**：Spring Data JPA 需要 `@Modifying @Query`，AI 未给出，手工补；并补充 `@Transactional` 保证"改状态 + 建订单"原子。
- **验证**：JMeter 50 并发，仅 1 单成功。BUG-01 闭环。

### ORD-003（10-19，成员B）评价：良，轮次 1

- **提示词**：`取消订单时把书籍恢复为 ON_SALE，但如果书籍已经 SOLD 就不要改。用状态机守卫，不要用一堆 if 嵌套。`
- **AI 输出摘要**：给出提前 return 的守卫式写法，可读性好。
- **人工修改**：补充"已完成订单不可取消"的判断，避免误把 COMPLETED 改回 CANCELLED。

## 三、前端页面（FE 系列）

### FE-001（10-20，成员A）评价：中，轮次 1

- **提示词**：`用 Vue3 + Element Plus 写发布页，包含 ISBN 识别按钮、成色滑块（1-5）、AI 定价按钮，点击后展示建议价与理由。`
- **AI 输出摘要**：页面结构完整，但 `el-radio` 使用 `label` 作为值（Element Plus 2.6+ 已改为 `value`），导致交易方式无法选中；AI 定价按钮点击无 loading 态。
- **人工修改**：改为 `value`；补 `:loading`；把"定价依据"从 tooltip 改为 `el-alert`，因为答辩时需要一眼看到理由。

### FE-002（10-21，成员C）评价：良，轮次 1

- **提示词**：`后台举报列表用 el-table，列为：类型、对象、原因、举报人、时间、状态、操作。操作列固定右侧，待处理显示"成立/驳回"。`
- **AI 输出摘要**：表格与操作列正确，`fixed="right"` 生效。
- **人工修改**：补充空态与状态标签颜色映射；为"成立"操作加二次确认。

### FE-003（10-22，成员B）评价：中，轮次 2

- **提示词**：`首页书籍卡片，封面 3:4，标题两行截断，显示价格、原价、成色、校区标签。`
- **AI 输出摘要**：样式基本符合，但标题用 `height` 固定导致不同字数卡片高度不一致。
- **人工修改**：改为 `-webkit-line-clamp: 2` + `display:-webkit-box`，统一卡片高度。

## 四、后端通用（BE 系列）

### BE-001（10-12，成员C）评价：良，轮次 1

- **提示词**：`用 @RestControllerAdvice 统一异常处理，业务异常返回 code/message，参数校验异常提取第一个字段错误，其他异常返回 500。`
- **AI 输出摘要**：三个 handler 正确，返回结构与 `ApiResponse` 一致。
- **人工修改**：补充 401/403 的语义约定；500 分支不返回堆栈，避免信息泄露。

### BE-002（10-13，成员C）评价：中，轮次 1

- **提示词**：`写一个 JWT 鉴权拦截器。`
- **AI 输出摘要**：引入 jjwt 依赖并给出完整实现，但会增加 3 个依赖。
- **人工修改**：课程项目改用 HMAC 签名令牌（Base64 + 签名 + 过期时间），零额外依赖，便于讲清原理；同时实现 `@CurrentUser` 参数解析器。

## 五、测试（TEST 系列）

### TEST-001（10-24，成员C）评价：优，轮次 1

- **提示词**：`为 OrderService 写单元测试，覆盖：正常下单、买自己的书、书已售出、并发下单、取消后回滚、非买家确认收货。使用 Mockito，断言异常消息。`
- **AI 输出摘要**：6 条测试一次通过，异常断言完整。
- **人工修改**：并发用例改为集成测试（`@SpringBootTest` + 线程池），Mockito 无法验证数据库层竞态。

### TEST-002（10-25，成员C）评价：中，轮次 2

- **提示词**：`用 Playwright 写端到端脚本，覆盖发布→检索→下单→确认→收货→评价。`
- **AI 输出摘要**：脚本可运行，但用 `page.waitForTimeout` 硬等待，偶发失败。
- **人工修改**：改为 `getByRole` + 显式等待元素可见；把登录态通过 localStorage 注入，避免每条用例重复登录。
